## 2024-05-07 - O(N*M) Clerk User Lookups in Next.js Server Components
**Learning:** Calling `Array.prototype.find()` on a large array of Clerk users inside iterations over database members (e.g., in `.map()` or `for...of` loops) causes severe O(N*M) processing bottlenecks. Additionally, fetching all Clerk users with just a `limit` ignores the actual relevant `userId`s, leading to unnecessary data or missing users.
**Action:** Always fetch server members from Prisma first, extract unique `userId`s, and pass them as an array in chunks (to respect Clerk API constraints) to `client.users.getUserList({ userId: chunk })`. Then, pre-compute an O(1) `Map` keyed by all identifiers (`id`, `discordId`, `robloxId`) *before* iterating over the database records to eliminate the N*M lookup complexity.
